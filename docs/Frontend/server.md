# [Runtime-сервер фронтенда (server.ts)](../../Frontend/Web/server.ts)

## Назначение
`server.ts` — это легковесный сервер на базе **Bun**, который обслуживает фронтенд внутри Docker-контейнера. Он отвечает за раздачу статики, проксирование API и работу SPA-навигации.

---

## Ключевая логика

Всё обрабатывает одна функция `fetch(req)`, которую получает `serve` из Bun на порту 5080. Порядок проверок ниже.

### 1. Проксирование API (`/api`)
Все запросы, начинающиеся с `/api`, перенаправляются на бэкенд (`BACKEND_API_URL`, по умолчанию `backpack_insight_backend:8000`) через внутреннюю сеть Docker, поэтому CORS в браузере не нужен. Если задан `API_SECRET` (или `ROOT_API_SECRET`), сервер добавляет заголовок `X-Internal-Secret`. Бэкенд недоступен — ответ 503 с JSON `Backend unavailable`.

### 2. Раздача статики
Сервер ищет файлы в двух местах:
1.  **`/static`**: Исходные картинки, шрифты и локализация.
2.  **`/dist_build`**: Скомпилированные Vite ассеты (JS/CSS чанки).

Оба пути проверяются на выход за пределы папки после `resolve`.

### 3. Отсутствующие файлы — 404
`isAssetRequest(path)` считает запросом к файлу пути `/assets/`, `/images/`, `/fonts/`, `/lang/`, несколько корневых файлов (`/sw.js`, `/robots.txt`…) и любой путь с расширением. Если такой файл не найден, `notFound(path)` отвечает 404 без кэширования. Отдавать вместо него `index.html` нельзя: браузер принял бы HTML за скрипт или стиль и упал бы на проверке MIME после обновления чанков.

### 4. SPA Fallback
Для остальных путей (пользователь заходит сразу на `/items` или `/profile`) сервер отдаёт `index.html`; пока сборки нет — заглушку «Building… Please wait.».

### 5. Управление Кэшированием
`getAssetHeaders(path)` выбирает `Content-Type` по расширению (`getExtension` отбрасывает `?` и `#`) из таблицы `MIME_TYPES` и `Cache-Control`:
*   **`CACHE_LONG`**: Для шрифтов и собранных ассетов (1 час).
*   **`CACHE_SHORT`**: Для динамических ресурсов (1 минута).
*   **`no-cache`**: Для главного HTML-файла, чтобы пользователь всегда получал актуальную версию приложения.

## AI-контекст
*   Сервер спроектирован для работы с **уже собранным** проектом. Он не запускает Vite в рантайме, что делает его крайне быстрым и экономным по памяти.
*   Использование Bun позволяет обрабатывать тысячи запросов в секунду на минимальных серверных мощностях.
