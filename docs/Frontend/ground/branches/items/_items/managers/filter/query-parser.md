# [query-parser.ts](/Frontend/Web/ground/branches/items/_items/managers/filter/query-parser.ts)

## Назначение
Разбор строгой части запроса в дерево `ASTNode` ([filter-types](filter-types.md)), которое проверяет [item-matcher](item-matcher.md). Пользовательский синтаксис — [search_filter_syntax](../../../../../../../search_filter_syntax.md).

## Экспорт
- `parseQueryToAST(query)` — список условий верхнего уровня, которые должны выполниться все.
  1. `normalizeOperators` заменяет слова `OR`/`ИЛИ`, `AND`/`И`, `NOT`/`НЕ` (без учёта регистра, как отдельные слова) на `|`, `&`, `!`.
  2. Если вне квадратных скобок есть `|`, строка делится по нему и даёт один узел `or`; иначе так же по `&` и узел `and`. Части разбираются рекурсивно.
  3. Иначе строка читается слева направо: `!` отрицает следующее условие, `[...]` разбирает `parseBracket`, числовое сравнение (`readComparison`) читается целиком вместе с пробелами, остальное — слово до пробела или скобки.
- `parseToken(text)` — лист: `!` в начале — отрицание, `<...>` вокруг — точное совпадение, любой из знаков `<`, `>`, `=` внутри — сравнение.

## Внутреннее
- `splitByOperator(query, op)` — деление с учётом вложенности скобок.
- `parseBracket(text, start)` — содержимое скобки без вложенных скобок становится `or` из слов (`tokenizeBracketContent` держит круглые скобки целиком); с вложенными — рекурсивный разбор в `and`. Незакрытая скобка — остаток строки одним листом.
- `makeAnd(children)` — не оборачивает единственный узел `and` повторно.
- `readComparison(text, start)` — формы `10<damage<20`, `damage>=5`, `5<cooldown`.
