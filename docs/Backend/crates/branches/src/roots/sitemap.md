# [Карта сайта для роботов (sitemap.rs)](/Backend/crates/branches/src/roots/sitemap.rs)

## Назначение
`Sitemap` строит `/sitemap.xml` прямо из реестра веток [`Gen`](gen.md): в карту попадает каждая ветка, у которой в [`BranchSpec`](spec.md) стоит `sitemap: true`. Новая страница появляется в карте сама, как только её зарегистрируют в `Gen` с этим флагом. Старая карта крейта `api` (из `.fb`-пакетов, со ссылками `/item/{slug}`, которых больше нет) на сайте не используется.

## Ключевая функциональность
- **`Sitemap::render(base, specs)`** — XML по протоколу sitemaps.org 0.9. Пути с параметрами (`:slug`) пропускаются: их адреса нельзя перечислить из шаблона. Хвостовой `/` у `base` срезается.
- **Языки.** Язык сайта задаёт `?lang=` (см. [request.rs](request.md)), поэтому на каждую страницу приходится по `<url>` на язык из `Lang::ALL` (`?lang=en`, `?lang=ru`). В каждом `<url>` перечислены все языковые версии через `<xhtml:link rel="alternate" hreflang=…>`, а адрес без `?lang=` помечен `x-default` (там язык выбирается по cookie и `Accept-Language`).
- **`Sitemap::response(base)`** — ответ Axum: `application/xml`, `Cache-Control: public, max-age=3600`.
- **`escape`** (приватная) — экранирование `& < > "` в адресах.

## Подключение
[runner.rs](runner.md) вешает `/sitemap.xml` отдельным роутером с состоянием `public_base_url` из `api::AppState` (переменная `ROOT_PUBLIC_BASE_URL`, по умолчанию адрес на `*.pages.dev`). Маршрут подключён после проверки `X-Internal-Secret`, как и открытые маршруты `api`. `/robots.txt` по-прежнему отдаёт `api` и указывает на этот же `/sitemap.xml`. В `api::app` (отдельный бинарник `api`) осталась старая карта, в `api::routes` её больше нет, чтобы маршруты не конфликтовали.

## Тесты
- `lists_indexable_pages_per_language` — главная и каталог на обоих языках, `x-default`, редактор и 404 в карту не попадают, ровно 4 `<url>`.

## Планируется
- Адреса отдельных предметов, когда у «поля предметов» появится адрес открытого предмета в URL .
- Профили не индексируются: это данные пользователей.
