# [Декларативный контракт ветки (spec.rs)](/Backend/crates/branches/src/roots/spec.rs)

## Назначение
`BranchSpec` — декларативный контракт ветки (аналог [BranchSpec.ts](/docs/Frontend/ground/roots/BranchSpec.md)) и сопоставление шаблона пути с реальным путём. Из одной спецификации получаются и маршрут Axum, и выбор ветки в `Gen`.

## Ключевая функциональность
- **`type Params`** = `Vec<(&'static str, String)>` — параметры пути: имя из шаблона (`slug` для `:slug`) → значение из запроса.
- **`struct BranchSpec`** (`Copy`, `PartialEq`), все поля `&'static`, чтобы спецификация была константой:
  - `name` — имя ветки (`ItemsBranch`); попадает в атрибут `data-branch` у `<main>` и выбирает фон 404 в [shell.rs](shell.md);
  - `path` — шаблон: статические сегменты и параметры `:name`;
  - `islands` — имена островов ветки. По ним `LazyIslands::links` ([lazy.rs](lazy.md)) решает, какой WASM ленивых островов грузить сразу вместе со страницей; для обычных островов это декларация для документации и аудита веса WASM;
  - `sitemap` — должен ли путь попадать в sitemap; его читает [sitemap.rs](sitemap.md).
- **`matches(path)`** — сравнивает сегменты шаблона и пути. Число сегментов должно совпасть; `:name` захватывает любой сегмент, остальные сравниваются буквально. Пустые сегменты (`//`, хвостовой `/`) игнорируются, поэтому `/items/` совпадает с `/items`. Возвращает `Some(Params)` или `None`.
- **`axum_path()`** — шаблон в синтаксисе Axum 0.8: `/item/:slug` → `/item/{slug}`, `/` → `/`. Используется в [runner.rs](runner.md).
- **`segments(path)`** (приватная) — итератор непустых сегментов, общий для обоих методов.

## Тесты
- `extracts_params_and_ignores_trailing_slash` — захват `slug`, хвостовой слэш, несовпадение по длине и по литералу.
- `converts_to_axum_syntax` — перевод `:slug` в `{slug}` и корневого пути.

Тестовые константы `ITEM` и `HOME` — спецификации-образцы, в реестр не входят.

## Связи
- Кто использует: [gen.rs](gen.md) (`matches`), [runner.rs](runner.md) (`axum_path`), [branch.rs](branch.md) (`Branch::SPEC`).
