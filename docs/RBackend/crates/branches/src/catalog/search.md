# [branches/catalog/search.rs](/RBackend/crates/branches/src/catalog/search.rs)

## Назначение
Поиск по каталогу и нарезка результатов на порции по `PAGE_SIZE` ([model.rs](../model.md)). Поиск простой: запрос режется на слова, и предмет подходит, если **каждое** слово (без учёта регистра) входит подстрокой в его `search_text` — имя, `id`, герой, типы, редкость ([item.rs](item.md)). Пустой запрос подходит всем предметам. Порядок результатов — порядок каталога по умолчанию: редкость от ценной к простой ([rarity.rs](rarity.md)).

## Ключевая функциональность
- **`MAX_PAGE`** = 40 — верхняя граница номера порции: `?page=100000` не заставит сервер рендерить весь каталог много раз.
- **`search_upto(catalog, query, page)`** — все карточки с первой порции по `page` включительно (`(page + 1) * PAGE_SIZE`). Используется SSR-страницей ([items/branch.rs](../branches/items/branch.md)): ссылка с `?page=N` сразу показывает всё, что пользователь видел после N подгрузок.
- **`search_page(catalog, query, page)`** — ровно одна порция `page`. Используется серверной функцией острова ([items/search_fn.rs](../branches/items/search_fn.md)), которая дописывает порцию к уже показанным.
- Обе функции ограничивают `page` значением `MAX_PAGE` и возвращают `ItemsPage`: `total` — всего совпадений, `has_more` — остались ли карточки после этой порции.
- **`matching(catalog, query)`** (приватная) — фильтр совпадений по словам.

## Тесты
- `every_word_must_match` — все слова обязательны, регистр не важен.
- `pages_are_cumulative_or_single` — `search_upto` накапливает, `search_page` отдаёт одну порцию, `has_more` на границе. Хелпер `item` строит тестовый `CatalogItem`.
