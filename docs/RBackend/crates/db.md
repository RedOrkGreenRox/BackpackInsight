# Обзор крейта db (crates/db/)

Crate `db` сохраняет разобранные профили в Postgres (production) или SQLite (локальная разработка). Драйвер выбирается по адресу подключения во время работы. Сырой JSON профиля и бинарные паки в БД не хранятся.

## Файлы
- [src/lib.md](db/src/lib.md) — подключение, включение по переменным окружения, миграции.
- [src/profile.md](db/src/profile.md) — транзакционное сохранение профиля, героев и предметов.
- [src/seed.md](db/src/seed.md) — первичное заполнение справочника предметов.

## Схема (миграции `RBackend/crates/db/migrations/{pg,sqlite}`)
| Таблица | Содержимое |
| :--- | :--- |
| `profiles` | `uid` (уникальный), ник, уровень, трофеи, бонусные трофеи, монеты, гемы, арена, `created_at`, `updated_at` |
| `itemdefinition` | справочник предметов: `item_id` (уникальный), имя, русское имя, редкость, цена, герой, источник открытия, покупаемость |
| `hero` | герои профиля, `profile_id` со ссылкой на `profiles` и каскадным удалением |
| `item` | предметы профиля: уровень, карты, нужно карт, суммарный опыт; `item_id` ссылается на `itemdefinition` |

Миграция `0001_profiles.sql` создаёт `profiles` с колонкой бинарного пака, `0002_normalized_tables.sql` добавляет три другие таблицы с индексами и удаляет эту колонку. Варианты для Postgres и SQLite отличаются только типами.

## Потребители
Только crate [api](api.md): подключение и сидирование в [state](api/src/state.md), сохранение в [routes/profile_binary](api/src/routes/profile_binary.md).
